# V3 코드 반영 계획: 측정 오차와 추천 정책 분리

상태: 계획 작성 완료, 아래 기능은 아직 구현하지 않음. 기존 v1/v2 실행 결과와 평가 프로토콜을 보존한다.

## 목표와 판단 기준

같은 20회 실험 예산에서 품질 미달 추천을 줄이면서 불필요한 추천 보류와 처리시간 손실을 함께 줄인다. 실제 욕조 데이터가 없으면 합성 검증으로만 보고한다. 공식 채용 평가표는 확보하지 못했으므로 이를 채용 점수나 최고 수준 증명으로 사용하지 않는다.

가장 중요한 가설은 '탐색 복잡성보다 측정 오차에 맞는 최종 선택 기준이 성능을 좌우한다'이다. 현재의 0.08 고정값을 정답으로 채택하지 않는다.

## 1. 평가 구조 분리 (최우선)

- `robust_benchmark.py`에서 시나리오, 관측 잡음, 탐색 정책, 최종 추천 정책, 평가 함수를 분리한다. 정책은 관측 이력만 받고 진실값이나 시나리오 생성 시드에 접근하지 않는다.
- 탐색은 uniform/random/adaptive/conservative를 유지한다. 최종 추천 정책은 raw/fixed-margin/calibrated-margin으로 분리하여 같은 탐색의 효과와 최종 선택의 효과를 각각 비교한다.
- 모든 방법에 같은 초기 관측 8개와 총 20회 예산을 부여한다. 반복 측정도 예산을 소비한다. 재측정을 사용하는 경우 추가 12회 중 6회는 새 조건 탐색, 6회는 동일 조건 재측정으로 고정하고 재측정 없는 기준선도 함께 보고한다.
- 시행별 선택 조건, 측정값, 선택 이유, 시점, 예산 사용량을 기록한다. 독립 시뮬레이터 호출 횟수로 예산 초과와 숨은 oracle 접근을 검사한다.

## 2. 측정 오차와 조건 이력

- 기존 CSV는 유지한다. 별도 v2 입력에는 measurement_id, replicate_group, bath_id, bath_age, temperature, agitation, measured_at, calibration_source와 품질 지표 정의를 추가한다. 단위는 스키마에서 명시한다.
- 서로 다른 욕조/형상/측정 방식의 반복값을 오차 추정에 합치지 않는다. 계측기 반복오차와 공정 반복변동을 별도로 표시한다. 둘을 분리할 자료가 없으면 분리 추정 불가 상태를 반환한다.
- 보정용 잔차가 있는 경우만 일방향 잔차 분위수로 추천 여유를 산출한다. 독립 기준 측정이 없는 단순 반복값만으로 편향 보정이나 신뢰수준을 주장하지 않는다. 보정 잔차가 30개 미만이면 calibrated-margin은 추천 보류한다.
- 추정한 여유값은 품질 지표, 적용 형상, 장비/욕조 조건, 보정 기간, 표본 수와 함께 저장한다. 범위 밖 입력과 분포 변화에서는 재보정을 요구한다.

## 3. 새 평가와 채택 규칙

- 이미 본 시드 0–219는 후속 개발/진단 자료로 분류한다. V3 정책과 임계값을 고정한 후 한 번만 평가할 시드는 1000–1099로 예약한다. 평가를 본 후 수정하면 새로운 버전과 평가 시드 구간을 사용한다.
- 네 기존 함수군에 무해한 잡음뿐 아니라 이분산 잡음, 센서 편향, 후반 공정 변화, feasible 조건 없음의 시나리오를 추가한다. 실험 중 조건 위반율과 최종 추천 위반율을 각각 보고한다.
- 주요 지표는 품질 미달·보류를 포함한 기존 손실, 최종 위반율, 보류율, feasible 발견률이다. 부가 지표는 실험 중 위반율과 계산시간이다. 실패/보류/실행 오류도 분모에서 제외하지 않는다.
- 보정 정책과 단순 기준선은 개발 자료에서 선택하고 확정한다. 평가 시드 단위 paired bootstrap으로 평균 손실 개선의 95% 구간을 구한다. 전체 손실 10% 이상 감소, 개선 구간 하한 >0, 최종 위반율 비증가를 모두 충족해야 채택한다. 각 함수군 결과도 공개한다.
- calibrated-margin이 fixed-margin보다 낫지 않으면 복잡한 보정 방식을 기본값으로 올리지 않는다. 탐색 간 차이가 불확실하면 uniform을 유지한다. 모든 채택은 연구용 추천에 한정하며 실제 생산 제어는 연결하지 않는다.

## 4. CLI와 보고서 연결

- `plan-experiments`의 기존 동작을 보존하고 `--strategy uniform` 및 `--recommendation-policy raw|fixed-margin|calibrated-margin`을 명시적 옵션으로 추가한다. 기본은 현재의 bounded-design으로 유지하며 벤치마크 승자가 자동으로 운영 기본값이 되지 않는다.
- `calibrate` 명령은 보정용 관측과 기준값을 받아 버전 있는 보정 결과를 출력한다. 기준값 없는 경우 오류 추정 한계와 추천 보류 이유를 출력한다.
- 연구용 출력에 추천 조건/보류, 사용한 정책, 근거 관측, 보정 범위, 불확실성, 미검증 항목을 포함한다. HTML 보고서에도 같은 구조를 표시한다.
- 실제 `plan-experiments` 출력이 데이터 검증 및 추천 조건을 통과하는 end-to-end 테스트를 추가한다. Boolean 모델 시험과 실제 구현 시험을 별도 보고한다.

## 5. 완료 기준과 실패 대응

- 자동 검사: oracle 누출 차단, 동일 seed 재현, 동일 예산, 보정/평가 자료 분리, 중복 측정, 잘못된 단위, 미관측 형상, 부족한 보정 표본, drift, feasible 없음, HTML 이스케이프, 중단/실패 포함 지표.
- 비교 결과에 구현 오류가 있으면 결과를 무효 처리하고 수정 버전으로 재실행한다. 유효한 평가에서 개선하지 못하면 해당 가설을 기각하고 결과를 보존한다. 데이터 부족은 알고리즘 성능 실패와 구분한다.
- 실제 공정 적용 전에는 동일 형상과 욕조의 독립 기준 측정, 반복 측정 및 현장 검토가 필요하다. 해당 자료 확보 전의 다음 최우선 작업은 계측/실험 데이터 계약 확정이다.
- 코드 통과율, 논문 재현 여부, 실제 공정 검증을 별도로 기록한다. MongoDB/GridFS에 전체 평가, 코드 해시, 데이터 출처, 실패를 보관한다. 공개 저장소에는 비식별 예제와 재현 코드만 포함한다.
- 공개 반영 전 Lean 명세/구현 적합성 검사와 비공개 정보 검사를 수행한다. 신규 컨테이너 빌드 문제는 독립 재현 장애로 추적하고, 성공 전에는 기존 이미지 실행과 구분한다.
